# Source Verification: bagh/tradition.json

Date: 2026-11-07. Record: DR-120 in `docs/research/design-process/decisions.md`, adopted under the
lead's delegation. Scope: all 60 concepts (180 claims) and all relationships of
`content/traditions/bagh/tradition.json`, which were `under_review` (104 items) or
`needs_evidence` (20 items) before this check.

## Standard

An item is `verified` only when every passage it carries was found verbatim, by script, at its
stated locator in an archived copy of a source the file already records, and the claim or the
relationship explanation says no more than those passages. A relationship carries one passage
(at most 25 words) for every source it cites, and is verified only when both of its concepts
are. Where a passage did not support the wording, the supporting passage was found in the same
source, or the wording was narrowed to what the source says, or the item was removed. No source
was added.

## Method

1. Each of the 13 recorded sources was fetched again on 2026-11-07 and its SHA-256 compared with
   `content/review/source-manifest.tsv`.
2. `python -I content/review/tools/evidence/verify_tradition.py check content/traditions/bagh/tradition.json <archive.tsv> content/review/source-manifest.tsv <report.json>`
   segments each copy (PDF pages with `pdftotext`, web pages by their nearest heading, as
   `segment_sources.py` does) and looks for every passage in its stated segment after the
   citation policy's normalisation only (`verify_quotes.py`: ligatures, curly quotes and dashes,
   line-end hyphens, whitespace). A PDF passage may run on into the next page.
3. `find` located replacement passages; `suggest-rel` proposed relationship passages, each of
   which was read against the explanation before it was used.
4. Every claim and explanation was read against its passages. The changes are listed below.
5. `table` printed the evidence table at the end of this record.

The archived copies and `archive.tsv` are in
`D:/Work/IIT-KGP/Paper_1-artifacts/sources/bagh-2026-11-07/`.

## Applying It In The Database

The loader reads `verified` as `under_review`, so importing this file changes nothing in the
database by itself. A named curator accepts the concepts with
`npx tsx scripts/content/verify-concepts.ts --as <curator email> --keys content/traditions/bagh/tradition.json --evidence content/review/bagh-verification.md --reason "<reason>" --dry-run`
and then `--apply`, which takes the concepts this file marks `verified`.
